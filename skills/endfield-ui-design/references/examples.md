# 使用示例

示例说明 Skill 如何处理请求，不是已经完成的项目案例或测试记录。

## 给侧栏加终末地点击反馈

读 controls、motion、shape-iconography。保持导航排版与路由；为收到输入、选中分别设计反馈。局部斜向擦入可以用一次动画，不让页面重建。实际检查新页面、当前项重复点击、Enter、减少动效与焦点。

完成时给出修改位置、预览和实际验证，不顺手重做账号卡。

## 账号卡颜色太单调、太硬

读 color、data-display、shape-iconography。保留用户要求的信息顺序，把外壳、资料、深色仪表、套餐铭牌和操作托盘分层。允许柔和容器，工业特征放在短轨、标签和对齐上。

同时检查 0/未知/过期/失败的区别；视觉重设计不自动重写账号服务。

## 直接复制官网整个皮肤

先辨明用户指向的具体版本与页面，实际查看参考；读 visual-evidence、rights、implementation。能复用且许可明确的代码按许可处理，官方角色、Logo、字体不由主题仓库许可证自动授权。

提供独立实现的布局、颜色和动作；确实需要官方素材的用途与许可问题具体说明，不把一切视觉参考都拒绝掉。

## 按官网 1:1 做一个按钮

用官方测量/用户截图确定按钮种类、视口和状态。现有 JSON 的普通 Button 2px/200ms 只能支持对应元素，不支持游戏里的所有按钮。缺少 hover/pressed 数据就重新采集或标明建议。

不把第三方库 150ms 和大切角称作官方参数。

## 只审不改

读 workflows、validation 与对应组件专题。提供位置、触发、后果、证据和建议；不修改文件、不安装主题、不访问真实账户。没有运行原生时写明浏览器/静态范围。

## 从零建立一个桌面工具主题

读 foundations、layout、implementation，再读核心组件。先完成工作台和一个关键流程，建立令牌；再扩到列表、详情、弹窗和诊断。不要把所有游戏家族都塞进产品，也不更换技术栈。

## 只要这份 Skill

交付标准目录、参考、证据和有用资源，完成格式与内容验证。本地安装只写新的 Skill 目录；不因此修改目标产品、真实客户端设置或自动发布远端。
