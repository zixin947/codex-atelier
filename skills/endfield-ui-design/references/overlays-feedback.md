# 浮层与反馈

## 选择容器

| 容器            | 用途                       | 不适合                       |
| --------------- | -------------------------- | ---------------------------- |
| tooltip         | 短解释、完整截断值         | 多步操作或必须阅读的风险     |
| popover         | 某个对象的小详情/选择      | 重要确认和长篇编辑           |
| drawer/详情面板 | 保持上下文地查看对象       | 完全无关的页面               |
| modal           | 需要聚焦的确认、编辑、预览 | 普通信息提醒                 |
| toast           | 非阻塞结果                 | 唯一错误说明、必须确认的任务 |

## 模态框

清楚的标题、影响对象、主要内容、动作。长内容中正文滚动，标题/动作可固定但不遮挡。主按钮写实际动作，例如“应用到 3 个条目”，而不是含糊“确定”。

打开后焦点进入有意义的位置，Tab 留在模态范围；关闭后恢复触发点。背景采用 inert/等效处理。Escape、遮罩关闭和未保存内容处理遵从产品约定，不临时创造另一套交互。

危险操作需要说明具体范围，已有授权与服务规则决定确认流程，不为普通可逆外观修改增加额外批准。

## 配置差异与修复预览

展示读取现状、外部变化/冲突、将改什么、备份、确认、写入校验与回滚的边界。原型可模拟流程，但明确不修改真实系统。

差异用行/字段和增删标记表达，不只靠红绿。预览阶段的“检查通过”不代表真实系统已修复。成功提示依赖实际写入和读回。

## 详情面板

保留当前选择，说明对象名称、状态、来源与操作。没有选择时提供引导空状态，不显示第一条数据假装用户已经选中。窄窗口详情变抽屉时保留关闭入口与焦点恢复。

## 浮层定位

跟随触发对象，碰到窗口边缘时翻转/偏移；随主区域滚动更新。不要让低层级容器的 `overflow` 裁掉菜单。滚动、缩放、键盘焦点和窗口变窄都检查。

## 通知

成功、信息、风险、失败有文字与图标。加载中使用合适的状态语义；普通通知可温和播报，严重错误才用更强提示。自动消失前保证有其他地方可以查回结果。

同一任务避免发出“开始、处理中、仍在处理、已处理”四个重复 toast；在已有控件上表达进行中，完成时给一个结果。

## 空状态、错误与禁用

| 情况       | 表达                 | 可提供的动作               |
| ---------- | -------------------- | -------------------------- |
| 首次空列表 | 还没有数据及原因     | 添加/配置/查看示例         |
| 无搜索结果 | 当前条件没有匹配     | 清空搜索或筛选             |
| 权限不足   | 具体不可操作范围     | 查看权限说明；不假造已授权 |
| 请求失败   | 对象、错误、旧值状态 | 重试、查看详情             |
| 部分成功   | 成功/失败/未处理数量 | 重试失败项                 |
| 尚未实现   | 规划范围清楚         | 不放假可用按钮             |

禁用按钮旁能发现原因；加载失败不等于空列表。错误说明保持可读，不只在鼠标悬停时显示。
