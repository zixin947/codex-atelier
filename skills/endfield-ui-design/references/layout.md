# 布局与桌面窗口

官网的角色大图、世界观点云和贴边说明提供构图依据，见 [画面](visual-evidence.md)。以下是桌面工具建议，不是游戏尺寸规范。

## 三个问题

先确定进入后首先判断什么、反复操作的位置在哪、细节与历史如何访问。用一个主体建立中心；辅助信息不争取同样面积。

| 结构               | 适合                 | 注意                             |
| ------------------ | -------------------- | -------------------------------- |
| 主仪表 + 辅助区    | 工作台、状态、监控   | 保留一个视觉中心                 |
| 目录 + 列表 + 详情 | 扩展、资源、文档     | 当前选择稳定，窄窗口详情可变抽屉 |
| 工具条 + 数据区    | 账号、记录、批量管理 | 搜索筛选与批量动作分组           |
| 问题队列 + 差异    | 诊断、冲突、回滚     | 风险与确认紧邻变更               |
| 正文 + 目录/侧注   | 说明、日志解释       | 正文宽度不随窗口无限拉长         |

## 起始尺度建议

侧栏 176–224px、顶栏 56–72px、内容间距 16–28px、列表行 40–52px、详情区 320–420px，主体与辅助区可从约 2:1 开始。按内容调整，不硬套到已有应用。

## 窗口适配

常见桌面参考是 1440×900、1280×800、960×700；目标项目另有基准时遵从它。

- 宽窗口展开主次区，不放大全部控件。
- 中等窗口先压缩空白与装饰，保住搜索、主按钮和文字。
- 较窄桌面可把辅助区下移或变抽屉，不自动改成手机底栏。
- 只有表格/代码容器可以按需横向滚动，应用本身不溢出。
- 隐藏导航标签后仍有可访问名称和可发现的解释。

## 滚动

通常由主内容滚动，顶栏导航稳定。检查 Grid/Flex 内的 `min-width: 0`、`min-height: 0` 与 `overflow`；不要用全局隐藏溢出掩盖丢失的操作。

固定底部操作不能挡住最后一行。弹窗考虑标题栏、缩放和字体放大。内部滚动容器不要层层嵌套得难以发现。

## 网格与背景

统一对齐比画满网格更重要。4px 或 8px 间距系列可作基准；需要精细对齐时用半单位。大字标躲开关键表单和读数；装饰画布位于内容下层且不接收点击。
