# 设计基础

## 先选载体

| 载体     | 信息任务           | 结构                             | 工具应用可借鉴           |
| -------- | ------------------ | -------------------------------- | ------------------------ |
| 宣传官网 | 观看、认识内容     | 大主图、巨大标题、贴边导航、章节 | 标题层级、版面节奏       |
| 游戏菜单 | 查询、选择、执行   | 高密度分区、稳定操作、明确选中   | 目录详情、控件和操作分组 |
| 战斗 HUD | 不中断行动传递信息 | 中央留场景，信息停靠四周         | 主仪表与低干扰状态       |
| 活动物料 | 建立主题           | 角色、主题色、强标题             | 专题或开屏，不接管全应用 |
| 档案文档 | 阅读、检索、追溯   | 路径、编号、条目、正文           | 诊断、日志、变更与历史   |

本次官方画面与游戏样本的证据范围见 [画面索引](visual-evidence.md)。工具建议是从视觉关系中取舍，不是把游戏菜单移植为所有产品的结构。

## 六个关系

**主次：** 一屏回答“先看什么、能做什么、结果是什么”。主体与辅助信息的关系，比装饰总量重要。

**表面：** 纸白和墨黑承担阅读；空白、底色差和局部细线承担分区，不给每块内容围相同粗框。

**信号：** 强调色指向当前、行动和进度；正常、未知、过期、失败不能混成同一种黄色。

**形状：** 圆环表达量值，圆形可承载头像和翻页，胶囊可承载筛选，切角可表达机械行动。柔和容器与硬朗结构可以共存。

**文字：** 中文正文清楚；编号、英文标签和状态数字构成副层。装饰英文不压过功能名称。

**动态：** 每次动态解释一次变化。确认输入、状态切换、业务结果分别表达，不靠长扫描掩盖结果。

## 误区

| 误区             | 修正                                   |
| ---------------- | -------------------------------------- |
| 黄色越多越像     | 先确认黑白层级成立，再添加有意义的信号 |
| 所有东西切角     | 查看官方圆形、胶囊和 2px 微圆角证据    |
| 一定要深底       | 官网有大片浅色章节，按任务选表面       |
| 全站像素体       | 正文和日志先保证阅读                   |
| 每块都是战术卡   | 目录、表格、文档、详情和仪表分别设计   |
| 背景等于风格     | 暂时关闭背景，界面仍应有秩序           |
| 点击动画表示成功 | 动画只确认输入，成功依赖真实结果       |

## 保留范围

只改按钮时保留业务和布局；完整重设计才重组层级。品牌、框架、路由和权限继续有效。优先保证文字、操作位置、状态真实性与键盘可达性。小改动用一两句说明取舍即可，不强制大型设计提案。
