# Atelier 路由页

## 已确认的范围

用户明确要求直接移植 magpie 路由页源码，路由由 Atelier 掌管。新增独立「路由」入口，复用现有模型与连接页配置供应商、候选池和优先级。前端将 magpie 的 stage / account rows / stats / attempt log 结构适配为 Vue，后端由 Atelier 网关产生真实候选、逐次尝试和最终结果。模块只负责路由决策的观测与展示。

## 决策与假设

- 采用源码移植及本机 IPC，替代原页嵌入；不依赖 magpie 安装、进程或 Web UI。
- 复用现有优先账号、优先级排序、同类账号池、上下文绑定与 401/429 切换规则；本次不扩张为 magpie 的所有协议及路由策略。
- 只展示实际经过 Atelier 网关的请求；不以浏览器演示数据冒充真实流量。
- 打开页面时每秒刷新，隐藏或离开时停止；最多保留 100 条已结束请求及最多 8 条在途请求。
- 默认打码账号名，不持久化请求、响应正文、凭据或路由历史。失败时保留已读内容并明确提示陈旧状态。
- 沿用 Atelier 的配色及字号，移植 magpie 的三列流程、候选列表、统计与逐次尝试交互；网关配置由现有连接页维护。
- 上游固定提交、MIT 许可及具体移植范围记录在第三方说明中；使用源码片段，不引入完整应用运行时。
- 验证预算最多 3 轮：核心网关集成测试与前端交互、构建、页面视觉检查。真实外部推理和 Desktop 接入单独报告。

## 数据边界

新增路由 IPC 仅返回运行状态、请求模型、内部请求 ID、候选资格与排序理由、尝试 HTTP 状态/错误码/耗时及最终结果。候选判断与实际转发使用同一份计划；在途请求、断流和取消由已有 RequestGuard 收尾，不从 HTTP 200 推断推理成功。
