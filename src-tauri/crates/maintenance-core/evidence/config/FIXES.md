## 额外依赖及原生细节

- `is_profile_assignment`：`is_profile_assignment.asm` @100376d60-100376eb0。只检查profile前缀+等号/Unicode空白边界；单独`profile`和`profile invalid`也返回true，没有要求有效TOML赋值。与诊断profile检查的更严格等号提取不同。
- `split_toml_section_header`：同名C @10078b924；双引号切换quoted，quoted内反斜杠使下一个字符按字面加入，反斜杠本身不加入；按quoted外的dot切组件，trim组件且保留空组件。不同于first_section_part原样保留quoted反斜杠。
- `strip_all_managed_blocks`在953行C中执行三遍；旧`pseudocode/06-strip_all_managed_blocks.md`将其概括为一遍并误称返回元组，未用该概括作为实现依据。返回是String。第一遍收集的HashSet是局部状态。
- managed块内非owned section若与任意块外用户section互为组件前缀，则其header及内容删除；不同section保留。不能粗暴删除整个managed块。
- 最后一遍的owned section只匹配未加引号字面量，因此`[model_providers."aimai1"]`可留存；这是原生行为，检查仍可报告问题。
- 最后一遍的owned section删除状态在空行清除，空行自身丢弃；后面的裸行可保留，这是原生行为。
- 剥离生成注释的前缀通过C各偏移小端字面量重建：`# Generated by AiMaMi`、`# 修改请通过 AiMaMi 应用页面`、`# Codex 智能路由`、`# 保持 openai 为 active provider`、`# 在 AiMaMi 里关闭智能路由`、`# 中转模型功能`、`# Codex 桌面 GUI 智能路由已启用`；另删除以`# CLI:`开头且包含aimami_relay的行。
- `foreign_provider_owners`：同名C @10037a08c + `owner_vec_fold.asm` @10050ca18-10050cd40。对find_foreign_providers的每条section说明trim空白/首`[`/尾`]`，按profiles./model_providers.去前缀后再次first_section_part，再放进HashSet；quoted dotted owner因此再次截断，保留此原生行为。
- third_party第二遍顶层profile/model_provider值仅trim双引号，没有单引号TOML解析；已知id用单引号包裹时可能不命中known集合，保留此原生行为。
- third_party没有初始问题时逐字返回原文本，不统一换行；有问题时两遍重建输出LF。global保留未删除行的原始行尾；profile/stale统一LF，即使只是缺少最终换行也可能产生FileChange。
